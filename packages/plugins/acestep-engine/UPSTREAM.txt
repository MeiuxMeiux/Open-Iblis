# ---- Server API (as built, NOT the engines.md draft) -----------------------
# ace-server --models <dir> --port <N> [--host 127.0.0.1]
#   GET  /health  -> {"status":"ok"}
#   GET  /props   -> { version, models:{lm,embedding,dit,vae}, cli, default, presets }
#   POST /lm      <AceRequest|[AceRequest]> {caption, lm_mode:"generate",
#                 seed?} -> {"id":<job>}  (array form since 9761469; Iblis
#                 sends the single-object form)
#   POST /synth   <AceRequest|[AceRequest]> (output_format:"wav32", synth_model,
#                 vae) -> {"id":<job>}
#   GET  /job?id=<job>&result=1  -> /lm: JSON array of enriched AceRequest;
#                 /synth: multipart/mixed (audio/wav part + raw-latent part).
# Flow: POST /lm -> poll job -> feed the result array to POST /synth -> poll job
#       -> extract the audio/wav part. (Two-phase, not the single /generate the
#       design draft assumed.)
#
# GAP (Step-2 decision): ace-server has NO request auth. The Iblis host expects
# sidecars to enforce X-Iblis-Session (echo-server does). Resolve before catalog
# ship: patch upstream to check the header, front it with a tiny auth shim, or
# formally accept loopback-bind + ephemeral-high-port as the boundary for this
# binary. Does NOT block the isolated Spike-0 smoke.
